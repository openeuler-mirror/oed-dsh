# build CI 轮询 需求分析

> 状态：草案（待评审） · 关联 issue：[#5](https://atomgit.com/openeuler/oed-dsh/issues/5) · 依赖：cve-build / oed_invoke

## 1. 背景与问题

`cve_build` 目前只给出本地预检命令 + 一句「用 `oed_invoke` 轮询构建状态」的提示，CI 轮询全靠 agent 手动多次调用 `oed_invoke`、自己判断终态。缺少「提交构建后轮询直到完成/失败」的顺滑封装。

## 2. 目标 / 非目标

### 目标

- **G1** 提交构建后，自动轮询 CI 状态直到进入终态（成功 / 失败 / 超时），返回汇总结果。
- **G2** 带轮询间隔 + 超时上限，不无限轮询。
- **G3** 复用现有 `oed_invoke`（只读查询），不新增网关依赖。

### 非目标

- 不做构建提交（那是写操作，仍由 `oed_invoke` / 未来封装单独处理）。
- 不解析构建产物 / 日志详情。

## 3. 功能需求

| ID | 需求 | 说明 |
|---|---|---|
| FR-1 | 轮询到终态 | 给定构建/任务标识，轮询 eulermaker / pkgcontrib 的状态操作直到成功 / 失败 / 超时。 |
| FR-2 | 超时反馈 | 超过超时上限给出明确反馈（返回当前状态 + 提示），不无限轮询。 |
| FR-3 | 只读复用 | 只调用 `oed_invoke` 的只读查询操作。 |
| FR-4 | 结果汇总 | 返回终态 + 关键字段（状态、耗时、失败原因等）。 |

## 4. 验收标准

- 提交构建后能自动轮询到终态，返回成功 / 失败 + 汇总；
- 超时有明确反馈；
- 只走只读 `oed_invoke`。
